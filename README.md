# MS Dedup

![Python](https://img.shields.io/badge/Python-3.11-3776AB?logo=python&logoColor=white)
![Flet](https://img.shields.io/badge/Flet-0.25+-00C8FF?logo=flutter&logoColor=white)
![Redis](https://img.shields.io/badge/Redis-7-DC382D?logo=redis&logoColor=white)
![Docker](https://img.shields.io/badge/Docker-Compose-2496ED?logo=docker&logoColor=white)

Веб-приложение для **дедупликации сущностей в МойСклад**. Вы указываете дубли и
целевую сущность — сервис находит все документы, где встречаются дубли, заменяет
их в позициях на целевую сущность, а затем (по вашему выбору) архивирует, удаляет
или оставляет дубли.

Интерфейс на [Flet](https://flet.dev) (веб), фоновая обработка — на
[Taskiq](https://taskiq-python.github.io) + Redis. Запускается одной командой через
Docker Compose.

---

## Возможности

- **4 типа сущностей:** Товары, Услуги, Модификации, Комплекты.
- **Дедупликация между разными типами:** по умолчанию дубли и цель — одного типа,
  но галочка «Разрешить разные типы сущностей» включает полную комбинаторику
  (например, заменить товары и комплекты на модификацию).
- **Замена в 15 типах документов** МойСклад (заказы, счета, отгрузки, возвраты,
  перемещения, розница, инвентаризация и др.).
- **Объединение количеств:** если в одном документе есть и дубль, и целевая
  сущность — их количества складываются, лишняя позиция удаляется.
- **Три действия с дублями:** архивировать (обратимо), удалить, или ничего.
- **Подтверждение перед заменой** с наглядной картой замен (или запуск без
  подтверждения).
- **Гарантия целостности:** если замена позиции не прошла — сущность не
  архивируется и не удаляется, а попадает в список пропущенных.
- **Расписание:** запуск процесса в назначенные дату и время (МСК).
- **Восстановление:** процессы переживают перелогин и перезапуск сервиса; после
  входа незавершённые карточки восстанавливаются автоматически, прерванные можно
  перезапустить.
- **Защита от лимитов МойСклад:** распределённый rate-limiter (корзинка 45/3с) и
  ограничитель PUT на сущность; индикаторы нагрузки в шапке.
- **Гибкий ввод ID:** UUID, ссылка из админки МС (`#good` / `#feature` / `#bundle`)
  или прямая API-ссылка; авто-разбивка при вставке нескольких ID.
- Встроенная **инструкция** прямо в интерфейсе.

## Быстрый старт (Docker)

Наружу публикуется **только порт приложения** — Redis и worker доступны лишь
внутри сети Compose.

```bash
docker compose up --build
```

Приложение откроется на **http://localhost:8080**.

Порт можно изменить через переменную `FLET_PORT` (например, в `.env`).

---

## Локальный запуск (для разработки)

```bash
poetry install
cp .env.example .env
# в .env укажите REDIS_URL=redis://localhost:6379/0

# 1) Redis
docker run -p 6379:6379 redis:7-alpine

# 2) Worker (в отдельном терминале)
poetry run taskiq worker app.broker:broker app.tasks

# 3) UI (в отдельном терминале)
poetry run python -m app.main
```

UI: http://localhost:8080

## Конфигурация

Все настройки читаются из переменных окружения (или `.env`). Значения по умолчанию
подходят для запуска через Docker Compose.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `REDIS_URL` | `redis://redis:6379/0` | адрес Redis |
| `FLET_PORT` | `8080` | порт веб-интерфейса |
| `MS_API_BASE` | `https://api.moysklad.ru/api/remap/1.2` | базовый URL API МойСклад |
| `MAX_PROCESSES` | `3` | максимум одновременных процессов |
| `PROGRESS_TTL` | `3600` | TTL прогресса в Redis, сек |
| `JOB_META_TTL` | `86400` | TTL метаданных карточки (восстановление), сек |
| `SCHEDULED_JOB_TTL` | `2592000` | TTL запланированной задачи, сек (30 дней) |
| `HEARTBEAT_TTL` | `15` | TTL heartbeat живого процесса, сек |
| `MS_BUCKET_SIZE` / `MS_BUCKET_WINDOW_SEC` | `45` / `3.0` | корзинка лимита запросов |
| `MS_MAX_PARALLEL` | `5` | параллельных запросов к МС |
| `MS_PUT_PER_MIN` | `90` | лимит PUT к одной сущности в минуту |

Авторизация в МойСклад — по логину и паролю (Basic Auth); вводятся на экране входа
и хранятся только в памяти сессии.

## Как это работает

Процесс проходит четыре фазы:

1. **Сканирование** — обход всех поддерживаемых документов, поиск позиций с дублями.
2. **Ожидание подтверждения** — показывается карта замен (пропускается, если
   включён запуск без подтверждения).
3. **Замена позиций** — дубли в документах заменяются на целевую сущность; при
   совпадении дубля и целевой в одном документе их количества объединяются.
4. **Очистка** — дубли архивируются или удаляются (или остаются — режим «Ничего»).

---

## Поддерживаемые сущности и документы

**Сущности:** Товар, Услуга, Модификация, Комплект. По умолчанию в одном процессе
допускается только один тип; включив галочку «Разрешить разные типы сущностей»,
можно смешивать любые типы (полная комбинаторика, в т.ч. дубли разных типов на
цель другого типа).

**Документы:** Заказ покупателя, Заказ поставщику, Счёт покупателю, Счёт
поставщика, Отгрузка, Приёмка, Возврат покупателя, Возврат поставщику, Списание,
Оприходование, Перемещение, Внутренний заказ, Розничные продажи, Розничные
возвраты, Инвентаризация.

Особенности: Комплекты встречаются в позициях только у Заказа покупателя и
Отгрузки; Инвентаризация поддерживает только Товары и Модификации.

---

## Действия с дублями

| Режим | Что делает |
|---|---|
| **Архивировать** (по умолчанию) | переводит дубли в архив, обратимо |
| **Удалить** | безвозвратно; не пройдёт, если сущность ещё используется (409) |
| **Ничего** | только замена в документах, сами дубли остаются нетронутыми |

Если замена хотя бы одной позиции не удалась, такая сущность **не** архивируется и
не удаляется — она попадает в список пропущенных.

---

## Статусы процессов

| Статус | Значение |
|---|---|
| Ожидание | поставлен в очередь |
| Запланирован | стартует в назначенное время |
| Сканирование / Замена позиций / Очистка дублей | идёт работа |
| Ожидание подтверждения | нужно нажать «Подтвердить замену» |
| Готово | успешно завершён (зелёная карточка) |
| Отменено | остановлен пользователем (серая) |
| Ошибка | сбой (красная) |
| Прервано перезапуском | сервис перезапускали во время работы — можно перезапустить или убрать (оранжевая) |

---

## Сохранение и восстановление

Состояние процессов хранится в Redis и переживает перелогин и перезапуск сервиса:

- метаданные карточки живут 1 день, прогресс — 1 час, запланированные задачи — 30 дней;
- после входа незавершённые карточки восстанавливаются автоматически (завершённые
  не показываются);
- если воркер умер во время работы (перезапуск), процесс помечается «Прервано» и
  предлагает перезапуск с нуля;
- запланированные задачи стартуют по времени, даже если вы выходили из приложения.

## Архитектура

```
app/
├── main.py        # Flet UI: экраны, карточки процессов, диалоги, polling
├── tasks.py       # Taskiq-задача дедупликации (фазы scan/replace/cleanup)
├── ms_client.py   # async-клиент МойСклад API + список типов документов
├── broker.py      # Taskiq + Redis брокер
├── scheduler.py   # отложенный запуск, heartbeat, учёт активных задач
├── progress.py    # хранение прогресса/состояния в Redis
├── limiter.py     # распределённый rate-limiter и PUT-guard
├── models.py      # pydantic-модели (статусы, прогресс, позиции)
├── config.py      # настройки из окружения
└── utils.py       # парсинг ID, словари названий типов
```

Сервисы Docker Compose: `redis` (внутренний), `app` (UI, единственный внешний
порт), `worker` (фоновая обработка).
